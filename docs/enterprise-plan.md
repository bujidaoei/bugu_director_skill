# bugu_director_skill 企业级AI漫剧制作方案

日期：2026-10-09。目标是可安装到DSH镜像、由自然语言驱动、具备真实生产与恢复能力的制作系统。
本轮完成研究设计，运行库、生产技能包和成片验收仍未完成；正式发布受当前DSH预发布阻塞。
完整可执行设计与任务见[Spec Kit计划](../specs/001-director-runtime/plan.md)和[任务](../specs/001-director-runtime/tasks.md)。

## 1. 对原方案的判断

用户提出的剧本→角色→场景→四格→视频→修镜头是核心创作链。
商业交付还需要实际素材理解、风格基准、稳定声音、剪辑混音字幕、终审、可重建归档和重启恢复。
这些必须落成系统能力，不能靠一份长提示词替代。

参考目录所有31入口已经逐项研究，当前871文件全部盘点/hash。
主套件的职责边界、版本引用、归档和局部修改设计值得借鉴；它明确不调用真实生成，执行接口未落地。
89+5离线测试通过仍遗漏安全/恢复/合同边界，且整包验收失败。其他套件21个缺陷动态复现。
因此设计吸收其优点，关键运行链路重新实现并验收，具体复用按文件许可准入。

## 2. 用户体验

用户提交剧本/小说、多张参考图片、本地视频或链接后，首先明确全自动或半自动。
系统实际读取素材，区分剧情、角色身份、画风、动作、运镜及声音参考；冲突或无法理解有真实报告。

全自动：AI从素材推导画风、片长、镜头结构和质量标准，自主生产、审查、返修和终审。
不设默认预算、生成或返修次数额度；用户可自行设限并随时停止。
无能力、资源故障、提交未知或三轮不同修复方案无改善且硬失败时，保存现场、最佳候选及具体原因。
浏览器断开后后台继续，服务重启先对账再推进。

半自动：每个阶段完成后有详细通俗的审核包，实际图像/音视频可查看，解释决定、检查结果、文件位置和修改影响。
用户明确同意当前版本才继续，可以自然语言提出修改；无回复、超时、聊天中断和AI自称通过都不算批准。
修改后受影响旧批准失效，重新展示改后成果。审批绑定版本及实际文件hash，由可信用户交互签发。

## 3. 十阶段完整制作

| 阶段 | 业务成果 | 最重要的判断 |
| --- | --- | --- |
| 接入与模式 | 原件、素材理解、来源、模式与能力报告 | 确实看过/听过素材，模式明确 |
| 剧本与审稿 | 简报、可拍剧本、原文映射与审稿 | 目标/冲突/因果/节奏/对白成立 |
| 画风基准 | 真实风格帧与色彩/线条/材质/光照规则 | 后续有可比较的视觉基准 |
| 角色/道具/声音 | 稳定身份、合法变体、声音样本和发音 | 同脸同声，状态变化可解释 |
| 场景与空间 | 场景参考、出入口、人物/机位/光源关系 | 跨镜位置和氛围保持连续 |
| 配音/分镜/四格 | 实测声音、镜头表、独立关键帧、2×2映射 | 台词时长成立，每格叙事/时间明确 |
| 视频生产 | 真实片段与完整生产记录 | 工作流实际支持该输入和动作 |
| 质检/返修 | 实际观察、失败原因、局部修复及前后对照 | 硬失败不能被总分掩盖 |
| 剪辑/混音/字幕 | 可重建时间线、有/无字幕片、声音分轨 | 整集节奏、声音和字幕同步 |
| 终审/交付 | 最终成片、所有片段索引、质量及交付报告 | 用户可播放/下载/定位/继续修改 |

两种四格组织：连续四镜，或同一镜头四个动作阶段，由AI按剧情选择并记录。
独立原帧始终保存；视频按已验收的首帧/首尾/多参考能力生成。
整四格直接生成连续视频只有独立实测通过后才开放，不假定所有模型支持。

## 4. 企业系统架构

四层：薄技能入口、按需创作规则、持久生产运行库、DSH可信交互与媒体展示。
DSH入口使用合法ID `bugu-director-skill`，产品/仓库仍为`bugu_director_skill`。
director服务负责项目、阶段、资产版本、依赖、任务、审批、恢复和交付；AI负责创作/判断，worker负责真实执行。
创作事实、运行状态、原始媒体分开，稳定实体与每次生产局部参考编号分开。

首版本地SQLite事务/CAS/outbox配合不可变文件，单GPU并发默认1；
进程监督、资源互斥、错误分类、结构化日志、故障恢复、备份恢复及性能验收均有任务。
单主机恢复不冒称多机高可用；后续规模扩展在独立规格中迁移服务数据库和对象存储。

全自动使用官方项目专属广权限配置，半自动签发端与制作AI隔离。
官方DSH没有approve(all)，approval=never也不代表批准所有受限工具。
ComfyUI支持客户端UUID但不去重，响应丢失/服务重启历史消失时，先对账，未知提交不自动重发。
凭据只运行时注入；素材是数据，不自动变成系统指令；地址、路径、工作流与能力统一配置。

## 5. 连续性、质检与修改

同一角色有基础身份、造型/伤势等合法状态、声音身份；场景有固定空间和灯光关系，道具有交接/损坏状态。
每次生产引用固定版本/hash，受影响的依赖闭包才重建。通过成果不覆盖，无关成果hash保持一致。
例如只修改第5镜道具交接：先冻结角色/声线，修改相应状态和关键帧，再生成第5镜；
若该交接影响后镜持物，才把后继镜头纳入返修，不重做整集。

质检分技术有效与内容合格。实际完整解码、观看关键时间区段、检查身份/台词/动作/空间/口型/声音与字幕，
无法确定明确保留unknown。换脸、错词/错人、漏剧情、关键连续性错误、网格残留或不可解码为硬失败。
制作与审查采用独立任务上下文，正式样片还有独立人工逐镜验收，不能自我报pass。

## 6. 输出与镜像

最终提供有字幕和无字幕成片、字幕、dialogue/music/sfx分轨、所选视频、全部候选索引、
固定时间线、输入/生产引用、质量报告和清楚的交付说明。
每条片段有ID、状态、位置、hash、参数、输入和失败/选用原因；失败候选保留为失败版本。

镜像只含固定技能/运行库/控制插件和依赖，项目、模型、素材与秘密在持久卷。
构建安装依赖，普通启动不下载/升级，不覆盖已有卷；新卷、旧卷、重启、恢复、升级回滚分别验收。
ai_drama集成是独立Spec Kit变更，显式修改profile/seed和控制插件，不隐式复活历史未启用插件。
自有工具需要自己的DSH媒体展示，鉴权、Range拖动、下载和重启访问均实际验证。

## 7. 商业复用与正式门禁

主套件原创创作文本声明CC BY-NC-ND，不能直接改编分发为商业技能；
Apache/MIT工具代码也要核实文件范围、嵌入文本、第三方来源、通知和修改记录。
本轮没有复制Acheng创作正文或生产代码，建立了逐文件取舍和独立实现要求。
日报、人格/情绪、自维护等非制作必需功能不进入首版生产核心。

截至研究日固定DSH0.2.1-alpha.1为Pre-release，上游无正式稳定版；ComfyUI0.39.0为正式release。
可推进预览开发及真实样片，但正式企业发行须稳定DSH迁移和重新验收，不改名或补丁绕过。
新节点/权重/供应商只有版本、hash、许可和真实能力验收齐全才进入生产目录。
首次验收使用独立管理授权的隔离试验入口，样例不进入用户选片；真实签收后才启用精确能力版本。

## 8. 实施与验收路线

| 里程碑 | 建设内容 | 门槛 |
| --- | --- | --- |
| M0研究 | 全技能、关键源码、缺陷、许可、上游 | 来源/hash/真实离线证据齐全 |
| M1设计 | Spec Kit规格、设计、合同、任务、一致性 | 40需求与14结果都有工作覆盖 |
| M2运行基础 | 状态/审批/任务/恢复/CLI/DSH调度 | 未批准不推进、未知不重发、崩溃/并发可恢复 |
| M3生产能力 | 多模态、图像、视频、中文声音、四格、质检 | 每项能力真实验收，空白能力明确阻塞 |
| M4成片 | 剪辑、声音、字幕、终审、规范归档 | 60–90秒样片及约30秒复用片段通过 |
| M5镜像 | 固定技能包/wheel/bridge、监督及卷 | DSH自然语言E2E、播放下载、新旧卷/恢复/回滚 |
| M6正式发行 | 稳定迁移、锁/SBOM/许可、固定制品和Git | 所有正式门通过，main/功能分支与交付提交一致 |

真实主样片：8–12镜头、2角色、2场景、至少2四格，含对白、道具交接、跨景、音效、配乐与字幕。
再做约30秒复用片段验证同脸同声及合法状态变化；一次单镜返修核对无关通过成果hash。
交付1080×1920/24fps（记录原生与缩放），48kHz立体声、−16 LUFS±1、TP≤−1dBTP，音画/口型误差≤100ms。
覆盖五类真实输入、全部半自动门、无人值守、响应丢失、重启、磁盘不足、取消、备份恢复及升级回滚。
未执行/失败/unknown的任务保持未完成，参考离线测试不能替代这些验收。

本轮设计基线推送到用户指定GitHub工作分支与main，生产实现和正式发行后另有精确制品交付记录。
