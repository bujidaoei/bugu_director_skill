# bugu_director_skill Constitution

## Core Principles

### I. Spec Kit 管理
需求、规格、计划、任务、编码、调试、测试、验收、变更和进度必须通过 Spec Kit 管理。
spec、plan、tasks 与实际代码、运行状态和证据一致。实现、真实测试及对应验收全部满足后才可完成任务。
文档审查通过只证明文档质量。禁止假数据冒充业务、空接口、临时补丁、未经调研的猜测或用待办注释替代实现。

### II. 官方边界与固定版本
使用官方接口和插件机制。ComfyUI、DSH 及生产关键依赖必须固定到正式稳定发布标签、提交和校验值。
alpha、beta、rc、nightly、dev、浮动主分支和上游 Pre-release 不得成为正式发布基线。
关键稳定上游缺失时可以推进设计和清楚标识的预览开发，但必须保留正式发布受阻状态。
禁止修改上游构建产物、伪造环境、注入脚本或用临时第三方补丁掩盖边界。
升级须独立变更，完成兼容研究、迁移、锁更新、回归、真实工作负载及回滚验证。

### III. 真实验收
离线测试不能替代真实图像、视频、中文声音、有声成片或 DSH 自然语言链路。
已生成、技术有效、质量通过、用户批准和已交付必须分别登记。
质量审查必须实际读取媒体；缺视觉、转写或生产能力必须阻塞对应工作，不能编造观察。
完成声明须绑定输入、产物版本、哈希、工作流、任务身份和检查证据。未执行/失败任务不勾选。

### IV. 安全和持久化
制作首先确定全自动或半自动。全自动按用户项目授权自主决策，不设默认预算或返修次数额度。
半自动每阶段持久等待真实用户批准；未回复、超时或退出成功不代表批准。
批准绑定阶段版本及输入/产物哈希，修改后旧批准失效；AI 不能签发人类批准。
项目、资产与声音按项目隔离。全权限使用官方项目专属配置；外来素材只作为数据。
密钥仅运行时注入，不进代码、镜像、日志或审核包。初始化不覆盖已有数据，默认只本机入口。
未知生产提交先对账，不能盲目重复提交。

### V. 清晰职责
技能路由、创作规范、编排、媒体执行、质检、剪辑、镜像集成与发布职责分离。
配置统一，外部接口有合同、错误分类、结构化日志、健康与恢复行为。
复用按文件核实许可、来源及修改记录；商业分发不包含许可不明或禁止商业改编的创作文本。
新实现须独立形成业务规则，不把参考包宣传或测试通过当作我们支持能力的证明。

## Deployment Constraints
首版单主机单 GPU，GPU 并发默认 1；并发提升先做真实能力验收。进程监督和恢复不代表多机高可用。
构建期安装依赖，普通启动不下载或升级。模型、素材、项目和凭据使用持久卷。
事务数据库使用符合引擎锁与一致性要求的本地持久文件系统。Docker 与 AutoDL 分别验收。

## Development Workflow
constitution → specify → clarify（存在需求歧义时）→ plan/research/data-model/contracts/quickstart →
tasks → analyze → implement → converge → 真实验收 → 发布。依赖/接口/部署变更同步文档。
只发布同一已验收镜像，禁止验收后重建。每次提交核对任务和证据。

## Governance
继承 2026-10-06 的 v1.0.0 基础治理。2026-10-09 更名并新增稳定发布、模式审批和商业复用规则，升为 v1.1.0。
修订按语义版本记录原因、影响和迁移。用户指令优先，每次实现及发布审查检查上述可验证原则。
不得因计划已编写、环境缺失或上游不稳定降低验收标准。不满足要求保留未完成状态。
