# Feature Specification: 可恢复的全自动与半自动 AI 漫剧制作系统

**Feature Branch**: `codex/001-director-runtime`

**Created**: 2026-10-09

**Status**: Specified; implementation and production acceptance pending; formal release blocked by upstream prerelease

**Input**: 用户提供文字、图片、本地视频或视频链接，通过 DSH 自然语言入口选择全自动或半自动，完成剧本、角色、场景、四宫格、视频、返修、有声剪辑和规范交付。参考 Acheng 全部技能，商业复用按文件许可处理。产品/仓库名为 bugu_director_skill。

## User Scenarios & Testing

### User Story 1 - 从真实素材建立制作项目 (Priority: P1)

用户提交一种或多种素材，首先选择模式，得到可追溯的素材理解与创作目标。

**Why this priority**: 输入的实际含义与模式决定后续全部制作，不能根据文件名猜内容。

**Independent Test**: 分别提交文字、图片、本地视频及链接，检查理解报告与实际素材一致；本故事可独立交付素材整理与制作简报。

**Acceptance Scenarios**:

1. **Given** 尚未选模式的新项目，**When** 用户提交素材，**Then** 首先询问全自动或半自动，确认前不开始生产。
2. **Given** 文字、图片和视频混合输入，**When** 接入，**Then** 保存原件、来源、哈希和真实理解证据，区分改编内容、角色参考、画风参考及动作参考。
3. **Given** 损坏、无法获取或无法视觉理解的素材，**When** 接入，**Then** 报告实际原因并阻塞依赖该素材的阶段，不冒充已理解。

### User Story 2 - 每阶段审核并提出修改 (Priority: P1)

半自动用户在每个阶段查看通俗、详细且包含实际产物的审核包，批准、修改或停止后再继续。

**Why this priority**: 用户明确要求逐阶段审核，审批是制作状态而非聊天客套。

**Independent Test**: 使用真实素材审核包，拒绝后修订、批准后推进；审核中断及重启仍待审，旧版本批准不能通过新版本。

**Acceptance Scenarios**:

1. **Given** 半自动阶段完成，**When** 汇报，**Then** 说明做了什么、原因、实际图像/音视频、质量问题、文件位置和修改影响，并持久暂停。
2. **Given** 用户未答、超时、会话关闭或 AI 自称通过，**When** 再次运行，**Then** 继续待审，不推进。
3. **Given** 用户明确批准指定版本，**When** 下一阶段启动，**Then** 批准身份、阶段版本及输入/产物哈希一致才允许推进。
4. **Given** 修改角色或剧本导致下游变化，**When** 重建，**Then** 受影响成果与批准失效，向用户再次展示变更后的审核包。

### User Story 3 - 全自动完成有声单集 (Priority: P1)

用户选择全自动后，由 AI 推导质量标准、自主创作、生产、审查、返修和终审，直到成片或明确能力阻塞。

**Why this priority**: 单集有声闭环是首版核心业务价值。

**Independent Test**: 原创 60–90 秒样片，8–12 镜头、2 角色、2 场景、至少2四宫格，具备对白、道具交接、跨景、音效、配乐和字幕；断开浏览器仍持续制作。

**Acceptance Scenarios**:

1. **Given** 全自动及可用生产能力，**When** 开始，**Then** 后续正常制作不逐步询问，按冻结质量标准自行终审。
2. **Given** 未设置预算或返修次数，**When** 制作，**Then** 不添加默认额度；记录实际资源/费用可知部分，用户可随时停止。
3. **Given** 连续三轮采用不同修复假设仍无改善且存在硬失败，**When** 判定停滞，**Then** 保存最佳候选、失败证据和阻塞原因，不谎称完成；该条件不是全局返修次数上限。
4. **Given** 浏览器断开、服务重启或提交响应丢失，**When** 恢复，**Then** 从已保存成果与任务身份对账，不丢审核状态、不盲目重复生产。

### User Story 4 - 跨集复用与局部返修 (Priority: P1)

用户可延续已有项目，同一角色保持身份和声音；修改一个镜头时只重建受影响成果。

**Why this priority**: 跨集同脸同声和局部修改决定系统能否持续商业制作。

**Independent Test**: 在样片基础上制作约30秒复用片段；更改一项道具状态或一镜头，核对合法变体与通过成果的哈希。

**Acceptance Scenarios**:

1. **Given** 已通过角色、场景和声音，**When** 续集，**Then** 引用稳定身份及明确变体，不另造不相关人物或声音。
2. **Given** 某镜头手部/口型/动作有问题，**When** 修复，**Then** 优先精确编辑；缺能力时重做受影响镜头，保留无关通过成果。
3. **Given** 合法换装、受伤、光照或道具交接，**When** 更新，**Then** 记录状态变化，质量判断不把合法变体误判成换脸或连续性失败。

### User Story 5 - 获得可播放、可重建的规范交付 (Priority: P1)

用户得到成片及全部片段的清楚位置、状态、来源和质量说明，能够播放、下载和继续修改。

**Why this priority**: 提示词或零散片段不等于成片交付。

**Independent Test**: 对交付包完整解码、播放、拖动、下载并从时间线重建；核对全部候选索引与实际文件。

**Acceptance Scenarios**:

1. **Given** 终审通过，**When** 导出，**Then** 提供有字幕/无字幕成片、字幕文件、声音分轨、所选片段、候选索引、可重建时间线及质量报告。
2. **Given** 未通过候选，**When** 归档，**Then** 保留失败/替代状态，不混入最终成片，不覆盖已通过版本。
3. **Given** 服务重启，**When** 打开已有成果，**Then** 文件仍可定位，受保护链接仍支持播放和下载。

### User Story 6 - 固定版本安装、恢复与正式发布判定 (Priority: P1)

管理者把技能安装进项目镜像，在新卷与已有卷使用同一固定版本，升级能够恢复或回滚，并了解真实发布身份。

**Why this priority**: 镜像交付与正式稳定上游是用户明确要求。

**Independent Test**: 镜像内自然语言制作、重启、数据恢复、升级回滚及版本核验；正式稳定依赖缺失时必须拒绝正式发布。

**Acceptance Scenarios**:

1. **Given** 新卷或已有卷，**When** 安装启动，**Then** 技能可发现，原项目/配置不被覆盖，模型/素材/凭据不进入通用镜像。
2. **Given** 关键上游为预发布，**When** 交付，**Then** 清楚标识预览及正式发布受阻，即使生成成片也不能解除门禁。
3. **Given** 已验收制品，**When** 同步 GitHub，**Then** 工作分支和 main 与本地交付提交一致，有真实远端读取证据。

### Edge Cases

- 混合素材内容互相矛盾、参考图不是同一人、视频无声音、字幕与对白不一致，须记录冲突及处理依据。
- 小说过长须分段索引、保留章节来源，不能因上下文截断遗漏关键设定。
- 图片无法解码、PDF仅扫描、链接失效/需要登录/不受支持，分别记录能力阻塞。
- 缺模型、显存不足、磁盘不足、队列离线、音色不可用时，不静默切换未配置云服务。
- 四格包含多个镜头或同一镜头四个动作阶段；不能把任意整张四宫格视为天然可生成正确视频。
- 审核后文件被改、批准重放、跨项目批准、重启后旧提交消失，均不能推进或自动重提。
- 正在取消但上游输出仍到达时，归档为取消后候选，不自动进入成片。
- 自动质检无法确定身份/口型/剧情时，结果为无法确定；不得以总分掩盖硬失败。

## Requirements

### Functional Requirements

- **FR-001**: 新项目必须首先确定全自动或半自动，明确记录用户选择及适用项目。
- **FR-002**: 接受文本、TXT、Markdown、DOCX、PDF、多图片、本地视频、直接媒体URL及受支持公开网页视频；保存原件和来源。
- **FR-003**: 对图片实际视觉理解，对视频实际探测、抽帧、音轨分析及转写；缺能力不得编造内容。
- **FR-004**: 将外来素材作为数据，区分原创/改编、身份/画风/动作参考；记录素材授权声明及来源限制。
- **FR-005**: 生成创作简报、剧本及审稿结论，检查目标、冲突、节奏、对白、因果和可制作性，改编保留原文对应。
- **FR-006**: 建立画风、色彩、线条、材质、光照、构图和真实风格基准，记录推导理由。
- **FR-007**: 角色具有稳定身份，造型、表情、状态及道具分别版本化，合法变化不覆盖身份基准。
- **FR-008**: 场景保存空间关系、出入口、活动区、机位、光源及时间状态，防跨镜氛围和位置跳变。
- **FR-009**: 角色绑定稳定声音、中文发音词典和实际声音样本；台词保存原文、说话人、情绪及实测时长。
- **FR-010**: 以实测配音时长设计镜头，保存叙事职责、表演、运镜、视线、持物、轴线和起止状态。
- **FR-011**: 生成独立关键帧及四宫格，AI按剧情选连续四镜或同镜四动作，保存格子顺序、镜头/时间映射和独立原帧。
- **FR-012**: 根据已验收能力选择首帧、首尾帧、多参考或整四格路径，未验收整四格路径不得宣称支持。
- **FR-013**: 调用真实生产后端生成图像、视频、中文声音及所需音效/配乐；记录工作流、模型、引用和真实输出。
- **FR-014**: 技术检查覆盖解码、分辨率、帧率、时长、音轨及完整文件；质量检查实际观察剧情、身份、动作、空间、音画与声音。
- **FR-015**: 硬失败包括身份漂移、错台词/说话人、漏剧情、关键连续性错误、网格残留和不可解码，不能由综合分抵消；无法确定不等于通过。
- **FR-016**: 返修定位失败原因、冻结通过资产，使用已验收局部编辑能力；缺能力时只重做受影响镜头并保存前后证据。
- **FR-017**: 完成镜序、入出点、转场、混音、字幕与音画同步，所有剪辑决定可以重建。
- **FR-018**: 完整终审之后提供规定交付包，清楚说明所有视频片段的状态、位置及最终选择。
- **FR-019**: 十阶段均形成审核包：接入、剧本、风格、角色/声音、场景、配音/分镜/四格、视频、质检/返修、剪辑、终审/交付；半自动每阶段必须暂停。
- **FR-020**: 审核包包含通俗解释、实际媒体、检查结果、待关注问题、文件位置及修改影响。
- **FR-021**: 半自动通过必须来自真实用户明确批准，绑定项目、阶段版本、输入/产物哈希；AI、超时或无回复不能批准。
- **FR-022**: 用户可拒绝并自然语言修改，受影响成果和批准失效，重建后重新审核。
- **FR-023**: 全自动从素材推导并冻结质量标准，自行终审；不设置默认预算、生成次数或返修次数额度，允许用户主动设置及随时停止。
- **FR-024**: 全自动持续执行可脱离浏览器；能力缺失、未知提交或三轮不同修复假设无改善且硬失败时，保存现场并进入明确待处理状态。
- **FR-025**: 项目、剧集、会话、素材、资产、声音和任务严格隔离；通过成果不可静默覆盖，后续用户反馈进入版本修订。
- **FR-026**: 持久保存任务、阶段、依赖、审核、质检、费用可知部分和事件，重启先对账，再继续允许推进的工作。
- **FR-027**: 提交响应丢失必须核实原任务，未知状态不自动重复提交；相同任务ID不是上游幂等的证明。
- **FR-028**: 提供启动、查询、审核、修订、暂停、恢复、取消、导出与数据备份恢复；取消后晚到成果不自动采纳。
- **FR-029**: 支持跨集同脸、同声、场景复用及合法造型/道具变化，只使依赖变更的下游成果失效。
- **FR-030**: 配置集中管理地址、路径、能力、并发及运行权限；凭据只运行时注入，不进入仓库/镜像/日志/审核包。
- **FR-031**: 全自动使用官方项目专属全权限；半自动批准签发方与制作AI隔离，输入不得改变宿主权限或其他项目。
- **FR-032**: 能力目录保存稳定节点/模型/工作流身份、校验值、硬件要求、真实样例、许可及验收状态；AI业务生产只能使用已验收能力。首次能力验收使用管理员授权的隔离试验入口，试验媒体不能作为业务选片，真实签收后才启用该能力版本。
- **FR-033**: 技能可安装并在镜像内自然语言发现，启动不安装/升级依赖，不覆盖已有卷，持续保存运行数据。
- **FR-034**: 关键依赖须上游正式稳定版；预发布缺口明确阻止正式发布，不通过修改上游或伪造环境绕过。
- **FR-035**: 升级独立完成兼容研究、迁移、锁更新、回归、真实工作负载和回滚验证，交付制品身份与验收一致。
- **FR-036**: 复用逐文件记录许可、来源、修改及署名，禁止商业改编或许可不明的创作文本不进入商业分发。
- **FR-037**: 通过官方受保护媒体入口展示实际产物，支持完整下载、拖动播放和重启后访问，失败不冒认成功。
- **FR-038**: 使用结构化事件、故障分类、健康与恢复信息；用户看得懂当前进度、待审、阻塞及下一步，不编造剩余时间。
- **FR-039**: Spec Kit、实现、任务和验收证据保持一致，离线测试、真实媒体、镜像和正式发布结果分别报告。
- **FR-040**: 正常同步 GitHub 工作分支及 main，查询远端提交验证一致；不得强制覆盖历史或保存用户凭据。

### Key Entities

- 项目/剧集：模式、目标、质量标准、阶段、当前版本和用户授权。
- 来源/理解证据：原件、来源、哈希、参考用途、观察/转写及能力结果。
- 角色/场景/道具/声音：稳定身份、合法变体、实际参考和版本依赖。
- 镜头/关键帧/四宫格/台词：叙事、起止状态、格子映射、实际时长和引用。
- 生产任务/媒体成果：请求身份、工作流、版本、真实文件、状态和检查。
- 审核/质检/返修：用户决策或AI观察、所绑定版本、证据及修复假设。
- 时间线/交付：镜序、音轨、字幕、成片、候选索引和重建记录。
- 能力/发行基线：依赖身份、许可、真实验收、预览/正式门禁。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 五类输入路径（文字、多图、本地视频、直接URL、公开网页）均有真实成功案例，损坏、不可获取、缺视觉各有真实拒绝案例。
- **SC-002**: 半自动十阶段在未批准时推进次数为零；拒绝修改、批准重放、版本失效、跨项目批准与审核中断各通过一次可复查验收。
- **SC-003**: 全自动生成一集60–90秒、8–12镜头、2角色、2场景、至少2四宫格的有声成片，全部硬失败为零，有对白/交接/跨景/音效/配乐/字幕。
- **SC-004**: 另生成约30秒续集复用片段，通过同脸、同声、场景复用及至少一项合法造型或道具变化检查。
- **SC-005**: 单镜返修后，所有无关已通过成果的哈希保持一致；每次修复有原因及前后真实媒体证据。
- **SC-006**: 提交响应丢失、worker/AI服务重启、审核中断、磁盘不足、取消及恢复均有验收记录，未知提交自动重复生产次数为零。
- **SC-007**: 全部交付视频和音轨完整解码；字幕及口型/音画同步在人工逐镜核验中误差不超过100ms，字幕对白无缺漏和说话人错误。
- **SC-008**: 所有生成候选100%登记状态、路径、哈希、生产引用；交付包可按时间线重建且选片与字幕一致。
- **SC-009**: 用户在镜像内仅从自然语言入口完成启动、审核或全自动制作、查询和导出；实际完成播放、拖动和下载，重启后链接有效。
- **SC-010**: 新卷、已有卷、重启、升级回滚及备份恢复各有真实记录；已有项目和凭据不丢失，通用镜像中用户数据和凭据出现次数为零。
- **SC-011**: 验收时所有关键依赖100%有正式稳定版本、提交和校验值；任何一项不满足，正式发布判定均为受阻。
- **SC-012**: 所有复用文件100%有来源和许可取舍；商业分发不含未获许可的受限制文本或素材。
- **SC-013**: 每项完成任务100%关联实际证据；GitHub main及工作分支与本地交付提交一致，远端读取验证成功。
- **SC-014**: 在测试前冻结硬件、文件系统、查询负载、真实媒体及备份字节清单的单主机profile下，20个项目/每项目1000资产的状态及待审查询95%在2秒内完成；可对账任务在服务恢复后60秒内重新呈现状态，完整数据集备份恢复在10分钟内完成，未对账任务保持未知。合成控制索引须标记benchmark，不算真实业务媒体；验收只适用于已冻结数据量，不能外推任意规模。

## Assumptions

- 延续先前会话和附件明确的 ComfyUI 优先、首版有声单集、全自动自行终审、无默认预算和次数额度、AI选择四格组织方式。
- 创作默认中文普通话及已授权预置音色；未指定画风、片长、画幅由AI推导并记录。
