## 3. 视觉与提示词套件细读

### 3.1 camera-moves-whitebox：镜头资产必须与清单一起验证

`SKILL.md:5,13` 与 `README.md:29-50` 宣称 132 个 1080p/24fps/4 秒白盒片段；`SHOT-LIST.md` 的全部镜头条目按八类覆盖 8+12+16+12+24+12+16+32=132。镜头类型与运动分开、同一白盒对照视差和遮挡，是很好的能力评测设计；这种素材能帮助导演选择推、拉、横移、升降、环绕与特殊视角，避免只有名称而无画面依据。

实际只带五个文字/清单文件。manifest 132 个唯一 key 均写 `ok:true`，声明总字节数 116,638,496，且规格一致为 1920×1080、24fps、96 帧、4.0 秒；没有实际 MP4，也没有验收图、contact sheet 或机器验证报告。132 个 `path` 均指向作者旧路径 `C:\Users\liu1\workrally\2026-09-16-16-45-23\output\camera-moves\...`，本机存在数为零（`manifest.json:8,15`）。文档的下载链接 `../../releases/latest` 在重新打包后也不能证明对应资产存在或版本相同。`README.md:98-108` 的质检描述因此属于来源声明；`112-121` 还披露步行/跑步滑步、鱼眼与 Cycles 边界，必须保留为素材能力限制。

bugu 适用实现：镜头定义用独立类型和参数；素材以相对逻辑 URI 引用；下载使用明确发布版本、预期字节数、SHA-256 和许可证；实到后用 ffprobe 验证时长、帧率和尺寸，抽帧审查运动及视差。验证失败或资源缺失要显示 unavailable，不能制造 132 条“已验收素材”。四宫格只是呈现方式，不能让一个四宫格自动变成四个供应商支持的关键帧。

### 3.2 cinematic-vfx-prompt-engine：效果因果强，通用强制弱

`SKILL.md:20-28` 把效果写成实体受力后的因果链：预备、拖影/蓄力、1–3 帧冲击停顿、消退；碰撞点、主体反冲和接触光必须对应。`32-93` 划分创建、优化、强化、个性化；`97-159` 的玄幻、赛博、机甲、暗黑风格矩阵使效果有题材一致性。这些可以支持爆炸、打击、能量武器等剧集镜头，同时避免“只堆发光形容词”。

但流体为主语、深色底和强制 `8K,120fps`（`51`）并不适合所有媒介、情绪或供应商。`65-75` 要求优化不得改变人物动作、时间和运镜，`194` 的示例却扩展到“低重心贴地滑步突进反手挥剑”等新动作与尾态，存在自身合同矛盾。`198-204` 的 `VFX_Engine` 是文字伪 API，无脚本或执行器。

独立实现应将特效拆成触发点、作用体、传播、接触、反冲、衰减和声音等字段，并将动作、镜头边界及事件时间作为锁定输入。风格矩阵只在题材满足时调用。供应商实际帧率、分辨率、长度由能力配置控制，不能靠正向提示词宣称达到。修改前后要验证锁定动作与对白没有扩写。

### 3.3 colossal-scale-visual-director：尺度证据及构图是优质设计

`SKILL.md:10-19` 区分建筑、器物、生物、纯有机体；`21-32` 从大轮廓、世界机制、事件、情感命题组织场景；`34-47` 要求至少两种独立且可比较的尺度依据；`49-71` 明确观察者的位置和镜头证据。`73-83` 的粗、中、细信息密度与 `85-99` 的光源→介质→接受面链条，比统一加超清或全局模糊更可审查。`101-111` 维护用户媒介；批量变体须至少改变三类维度（`120-134`），能降低“换几个形容词”的伪变体。

全部场景指南和字段指南已经阅读。检查项 `150-165` 是主观创作审查，不是实现过的像素检测；入口 `167-172` 明确不负责调用、归档或重试，可选外部技能在本包也未全部提供。bugu 可独立制作尺度证据字段、轮廓密度和光路审查模板，并绑定真实渲染图与审查结果；不能仅输出 PASS 文本就判定画面达标。

### 3.4 h3-prompt-writing：参考角色与音画语义可复用，模型参数须重证

入口五类为 T2VA、I2VA、FL2VA、L2VA、Ref2VA（`SKILL.md:8-20`）。`base-en.txt:16-34,54-62` 将输入帧与首/尾时间状态对齐，避免参考图被任意改脸或重布局；`86-123` 规定单调时间、镜头幅度及速度；`127-162` 使用稳定主体 ID、精确对白、画外音闭嘴、转场和声音类别。`ref-en.txt:24-48` 区分主体内容 Subject 与文件 Picture/Video/Audio；`90-118,155-207` 要逐项声明音频角色与保留范围，避免把“给了视频参考”理解成未经确认复制其中声音。

这些是很有价值的供应商无关语义。问题是包中没有 H3 适配器和真实调用验证；入口的 4–15 秒限制（`43`）、英文长度和标记语法不能视为当前正式模型合同。对白保持也有矛盾：`base-en.txt:129` 保留用户标点，`ref-en.txt:274` 又要求规范化标点。`agents/openai.yaml` 只是展示配置，不证明支持模型接入。

bugu 建议保留稳定 speaker/subject/shot ID、来源文件引用、复用边界、起止状态、音频作用和时间轴，由自己定义 schema。引用文件应绑定 hash、角色、允许借鉴的部分及授权信息；供应商 adapter 再把字段编译成其官方支持语法。能力探测通过前不可认为“某模式有指南”就“某模式能生产”。

### 3.5 im2-clean-image：把修图要求变成可审查约束

`SKILL.md:8-29` 从结构、材质、光路、负面提示卫生组织图像；`31-77` 把材质响应与局部接触光分开；`79-107` 以焦点/支持/安静区域安排信息密度与深度损失。`123-148` 的 EDIT/REBUILD/MIXED、CHANGE/PRESERVE EXACTLY/REBUILD 合同，非常适合剧集资产局部修复：先明确哪里坏了、哪里绝不可变，再决定局部编辑还是重建。

五份参考完整审阅。`evidence-preserving-photo-restoration.md:15,44` 的保真立场尤其值得采用：原照片身份、文本、数字、QR 和证据位置不能以“清晰”理由捏造；宁可保留不能验证的模糊。`heavy-scene-structure-and-mass.md:65` 从已接受干净底图重新修复，避免连续修图累积漂移；真实场景光参考以因果链而非统一发光塑造空气感。

它仍是提示词规范。要求精确保留文字、像素、几何和身份，不能靠生成模型承诺；对真正精确区域要有 mask、合成或其他确定性路径和输出比对。负面提示的默认大段卫生列表（`SKILL.md:150-173`）及默认柔光不能覆盖用户画风与戏剧意图。应独立实现条件化材质/光路规则、约束锁、编辑范围与效果诊断；允许局部小步重试，尊重用户可选预算或额度，无默认预算或生成、返修次数上限。资源或能力缺失，或经过三轮不同假设验证仍无改善且存在硬失败时，保存最佳候选并明确阻塞或停滞；供应商硬限制和物理资源边界如实记录。

## 4. lobster-skills：11 个子模块的实现与承诺逐一核对

### 4.1 根入口与视频流程

根入口和 README 的数量及路由表不一致（`lobster-skills/SKILL.md:5-15`、`README.md:3-20`），说明没有机器化能力注册和发布一致性检查。许多子入口没有标准 YAML frontmatter。企业安装器要验证唯一技能名称、目录、入口、资源和实际 CLI 能力，不能依赖自然语言分派表。

`ai-video-workflow` 的 Gemini→Midjourney→FLUX/ComfyUI→可灵/海螺/Runway 顺序和三份模板提供制作阶段组织，但没有真实调用器。`SKILL.md:67` 禁 tapnow 的理由是“竞品”，属于原用户商业偏好；日报原始需求反而围绕 tapnow，这些不能作为本项目通用原则。图像模板默认 8K/high detail 与 im2 的媒介保护立场也不一致。

`workflow_guide.py:72` 浅拷贝类级 `STEPS`，两个项目会共享步骤对象；`79-84` 无条件完成任何索引。SUP-01 证明完成最后一步会同时把两个独立实例的最后一步改成 completed，且无需前序或产物。它只能做展示型流程提示，不能做半自动审批或全自动状态机。

### 4.2 asset-manager

`SKILL.md` 和 `asset_template.md` 的项目/日期/类型/标签/提示词来源信息值得借鉴。脚本只按扩展名猜类型并写 JSON 元数据；`asset_organizer.py:62-66` 算出规范名称后没有使用，`56-93` 不检查存在、不复制、不重命名、不计算哈希、不探测媒体。SUP-08 实际证明 absent.mp4 可以登记成 asset_1 并进入索引。

后续必须在真实下载/复制、大小与 decode 验证成功后注册；资产绑定原始 URI、输入 hash、派生父资产、供应商任务、模型版本、提示词版本、权利信息与接受状态；索引需事务和并发控制。目录规范应提供 originals、accepted、rejected、shots、audio、renders、reports 与交付 manifest，用户最终收到的是可打开文件和可核验清单。

### 4.3 hot-memory-system

### 4.4 security-baseline 与 pre-publish-security

两个入口都强调外部输入、代码和发布检查，但脚本是关键词/正则报告器，无执行器权限门禁。SUP-04/SUP-05 证明 Windows `\.aws\config` 漏报和正常 base64 图像说明误报。它们不能承担提示注入防御、路径沙箱或安全批准。

## 8. 面向商业漫剧系统的落实建议

优质创作思路应进入结构化合同和可执行门禁，而不是堆进一个巨大 SKILL.md。入口用自然语言选择模式与项目，职责分为剧本开发/审查、角色与场景资产、分镜与参考关键帧、媒体生产、剪辑声音、局部修复、质量与交付。辅助套件中支持得最好的部分是镜头语言、物理光路、尺度和主体/参考语义；真正欠缺的是执行状态与持久化证明。

建议设计必须落实以下机制：

1. **模式与审批持久化。** 首次选择全自动或半自动。全自动由 AI 在已授权项目范围决策并留审计；半自动每阶段产生通俗摘要、产物链接、差异、质量结果和修改影响，等待该阶段版本批准，批准需绑定 hash。来源的宽泛确认默认规则不能覆盖用户模式；预算或额度由用户自选，默认不设置预算或次数上限。
2. **状态机驱动流程。** 阶段仅在前序、产物、质量门禁、审批和版本满足时转换。已接受角色/场景/关键帧不可被后续优化静默改写；修改触发相关下游失效和明确重建范围。
3. **供应商能力与执行分离。** 提示词指南不能充当调用器。每个 adapter 提供已验证模式、限额、分辨率、时长、帧率、关键帧数、轮询、下载和恢复；参数来源配置而非提示词幻想。
4. **真实资产注册。** 下载、文件大小、校验值、可解码、时间轴校验后登记。生成任务、输入资产、prompt/model/workflow 版本和费用形成完整来源链；失败产物保留但不可自动进入 accepted。
5. **经验晋级基于实测。** 拒绝假成功分数；只认可实际执行结果、真实媒体评价和用户接受。提示词版本、角色身份、素材边界、失败原因与修复效果都可追溯。
6. **局部修复与可选预算。** 以差异、约束锁与故障位置选择重生成或局部编辑，验收真实输出。尊重用户可选预算或额度，无默认预算或生成、返修次数上限。资源或能力缺失，或三轮不同假设验证无改善且仍有硬失败时，保存最佳候选、当前证据及未达标项，明确阻塞或停滞；不能宣称已达到用户标准。供应商硬限制与资源物理边界独立记录，不把它们混同为用户预算上限。
7. **发布与交付分离。** 交付视频可打开、目录与 manifest 可核验，报告明确每条是否实际生成/接受。正式企业发布另外验证 DSH/ComfyUI 正式稳定上游版本、发布标签/提交/hash、许可、真实工作负载与回滚；上游没有正式稳定版时保持预览/受阻状态。

本报告只完成需求中的辅助套件调研和缺陷证据，不将任何 bugu 运行时功能标记为完成。尚未完成的真实验收包括：所有供应商调用与真实图片/视频/TTS/音乐、人物一致性与剧情连贯评价、视频解码和剪辑交付、DSH/ComfyUI 正式稳定版集成、付费授权和第三方许可来源确认、任务恢复/并发/多租户/成本与安全门禁。它们应在 Spec Kit 的规格、计划和任务中保持未完成，直到有可复核的实现与验收证据。
